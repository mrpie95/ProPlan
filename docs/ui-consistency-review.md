# ProPlan UI consistency review

Method: live app at localhost:8137 with the preview seed (8 WPs, 53 tasks), 800 and 1400 px, light and dark for Timeline/Plan/Progress, computed-style sampling (height/radius/font/colour) across all 13 views, source greps of `Carpati Timeline.html` and `src/proplan-core.mjs`. The Timeline-tab View panel was in flux and is only noted, not judged. Not covered in depth: Proposal/Phase/Roadmap visuals in dark mode, the date picker `.dp` and context menus visually (CSS only), toasts (no `.toast` rule found in the first stylesheet), view-only mode (toggling `proplan.editMode` via localStorage did not switch the Timeline into view-only in my session, so addendum item 8 is unverified).

## Summary

The app has a solid base (shared theme tokens, consistent modal shell: 520 px, 14 px radius, 22 px padding, 33 px / 8 px-radius buttons) but each view grew its own chip/pill/status vocabulary. Measured: pills/chips come in at least 14 different height/radius/weight combinations (16 to 36 px tall); "in progress" is blue on Progress but amber on the Timeline; done is green but drawn with four different glyph systems; task IDs appear as `1.3`, `M1.3`, `WP1.3`, `WP 1`, `WP1` depending on view; the nav says "Timeline" for the Alt timeline while the old one is "Legacy timeline" under a "Choose view" button; edit mode is a "Done" button plus an "EDITING" pill. Focus rings exist for only a handful of controls, several click targets are 16-22 px, and the Timeline's WP name block clips on short WPs. Most fixes are token-level (one pill, one status icon, one ID formatter).

## Recommended design tokens / components to unify

1. Status tokens and one `StatusIcon` component: todo (grey ring), doing (amber half), done (green check), blocked (red). Same colours for Plan, Progress, Timeline rows, Summary tiles, Phase status, Roadmap pills, HTML export. Done = icon + subtle row tint, never an additional text check.
2. `.pill` (sm 16 / md 20 / lg 24) with variants neutral, accent, status, WP. All chip classes (`sum-chip`, `pp-chip`, `struct-chip`, `wp-num-pill`, `task-meta-chip`, `prog-status`, `roadmap-status-pill`) become aliases.
3. Button scale sm 24 / md 32 / lg 40 with two radii (`--radius-sm` rectangles, 999 toggles); icon-only buttons require `aria-label` and a 24 px minimum hit area.
4. Identifier formatting: `wpLabel(n)` -> "WP 1"; `taskId(bar)` -> "1.3" or "M1.3"; "WP1.3" only in tooltips; one `.id-chip` style; show IDs on Progress, Legacy timeline, Summary table and the HTML export too.
5. Colour roles: WP colour = identity (strip, WP header, row rail, bar fill pastel); phase colour = phase pills and phase bands only; type = pattern/shape (hatch, diamond, dashed), not hue; status = icon/overlay; dependencies = neutral ink, red only when violated.
6. Icon set: inline SVG, 16 px, 1.6 stroke, currentColor; remove emoji from menus.
7. Dialog and popover shell: one `openDialog` with title, close, `aria-labelledby`; popovers share radius, shadow, 1 px border token (ctx-menu, chip-dropdown-popup, at-pop, dp currently set these separately).
8. Focus ring token (2 px accent, 2 px offset) applied globally; hover = `--accent-soft`.
9. Row-height and type-scale tokens (see F21, F23); naming glossary: Timeline / Classic timeline, Edit / Done editing, Inspector (selection) vs View options (display).
